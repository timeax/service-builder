- Runtime cutover rule: authorization, boot, catalog, option traversal, canvas, and property consumers must move as complete vertical slices. Replacing a leaf type while its caller still receives legacy runtime data is rejected because it can silently disable actions or misread camel-case catalog state.
- The legacy `@timeax/digital-service-engine` dependency and every source/test import have been removed with the user's explicit authorization. No compatibility adapter or legacy persisted-definition support was introduced.
- `npm run check:boundaries` traverses both shipped source entrypoints, rejects any transitive path to `@timeax/digital-service-engine`, and enforces a zero-file legacy production budget. The current result is `0/0`.
- `package.json`, `package-lock.json`, `src/**`, and `backend/**` contain no legacy-engine dependency or import. The removal ledger is preserved in `LEGACY-SOURCE-INVENTORY.md`.
- Legacy types and wire fields are replaced at each UI boundary rather than translated into canonical definitions.
- The visual contract is the rendered Service Builder interface, not its legacy TypeScript definitions. Internal view models may change freely, but must remain canonical and must preserve the established DOM, styling, controls, and workflows.
- A scoped UI/integration finding closes with relevant implementation evidence, an existing canonical result, or a documented non-applicable legacy expectation. An unresolved visible-workflow blocker remains open; every historical row does not need new tests. Compilation alone does not prove UI correctness.
